# 所有权与数据流

`UPRProgressionSubsystem : UGameInstanceSubsystem`是唯一Progression运行时所有者：

```text
Schema 4 Save Snapshot
  -> Progression Registry
  -> Unlock Validation
  -> Atomic Currency + Unlock Staging
  -> Verified A/B Save
  -> Progression Snapshot/Event
  -> Next Run Modifier Snapshot
```

- RunState继续拥有反证碎片来源和账号结算；Progression只读取并消费余额，不迁移、不重命名也不复制该字段。
- 解锁请求只有在Save写入并回读验证成功后才改变运行时快照、扣减余额或发布事件。
- 当前RunSnapshot在运行开始时冻结；活动运行期间完成的解锁只影响下一次成功StartRun。
- RuntimeState和持久化数据只包含值类型、稳定ID和有界数组，不保存UObject、ASC、GameplayEffectHandle、Timer、Delegate、弱引用或原始事件。
- 普通地图旅行保持已加载Progression状态；Profile切换、运行结束、Deinitialize和失败回滚必须幂等清理临时GE、支援策略、请求和委托。

# Save Schema 4与事务

- `UPRSaveGame::CurrentSchemaVersion = 4`。
- 新增严格3→4迁移；Schema 1/2必须逐步迁移到3后再进入4，禁止跳步。
- Schema 4安全默认：`MemoryFragments=0`、`UnlockedNodeIds=[]`、`UnlockSequence=0`。
- `CounterproofFragments`继续位于`FPRAccountPersistenceData`；不得移动、重命名或复制为第二余额。
- SaveSubsystem新增窄C++原子Progression事务暂存入口，一次暂存更新后的AccountPersistence和ProgressionPersistence；不增加Blueprint写入、任意Slot、导入导出或物理删除API。
- 保存与写后验证成功前不得扣减运行时余额、发布解锁事件、应用GE或更新支援策略。
- 保存失败时保持原运行时状态，保留准确待重试快照；重复请求、重复回调、已解锁节点不得重复扣费。
- 损坏代、A/B恢复、未来Schema/Envelope拒绝和“旧客户端不得覆盖未来文件”合同保持不变。
- 新Profile直接创建Schema 4安全默认；既有Profile保留ProfileId、Companion关系、AccountPersistence、墓园和RunSummary。
