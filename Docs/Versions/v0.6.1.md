# 目标与非目标

一次完整交付第二章“守夜者”：已有 Allocator Proof 的隔离 Profile 从 RealityHub 创建账号并进入网络，自动进入确定性的 6–10 房 Warden 路径，经历陷阱、预警路线、提前封锁和无经济配给终端，击败具有预判攻击、平台封锁和风险标记的 Warden Boss，经既有账号终止流程返回 RealityHub，并幂等获得 `HumanAnomalyProof.Warden`。

不实现 v0.6.2+ 章节、Pacifier、后续 Boss/Enemy/Rule、结局变量、正式经济/货币/库存/价格/交易、掉落、难度、平台功能、真实网络、LLM、Provider、凭据、自由文本或任意内容生成。

# E-036 最小兼容语义

- 真实 v0.6.0 实现仍在 ChapterSubsystem、Room Registry、指令、Enemy Registry、Boss 和 Proof 结算中硬编码 Allocator。本版本只把这些判断扩展为固定 Allocator/Warden 白名单；原 Allocator getter、资产、Seed、路径、Boss 和 Proof 行为必须逐项回归不变。
- RealityHub 没有章节选择入口。本版本不修改 RealityHub 或 RunState；ChapterSubsystem 只读取公开 Schema-7 Chapter 快照：无 Allocator Proof 时保持 Allocator，有 Allocator Proof 后选择 Warden。已有 Warden Proof 时可重玩 Warden，但不得重复结算。
- 冻结 Chapter Room 路径要求一个 Shop。本版本创建 `RiskProvisionTerminal`，仍是既有三选一、不可重掷 Reward Offer，不产生货币、库存、价格、购买或交易记录。
- 陷阱、预警和提前封锁只产生有界值状态和固定候选约束。“平台封锁”是以 Boss 相对 X 位置计算的瞬态三分区风险窗口；不得修改地图、平台、碰撞资产、Input 或 GameplayTag。

# 章节选择与生命周期

1. Profile/AccountReady 时通过 `GetChapterPersistenceSnapshot` 读取规范值：
   - 未持有 `HumanAnomalyProof.Allocator`：配置 Allocator；
   - 已持有 Allocator Proof：配置 Warden。
2. RunActive 时冻结当前定义、RunId、AccountId 和 Seed；运行中 Proof 或 Profile 变化不得切换章节。
3. 每次 World rebind 在 Room 开始前配置准确 Room/Enemy Registry；未知、重复、未闭合或加载失败时拒绝启动，不回退到任意类/路径。
4. 普通地图旅行保留 GameInstance 冻结状态并幂等重绑；WorldCleanup、Profile 切换、账号终止、PIE Stop 和 Deinitialize 清理 Widget、Timer、Delegate、Actor、区域、预测值及弱引用。
5. 死亡、撤离、InterruptedRecovery、错误路径或错误 Boss 不结算 Warden Proof。

# Seed、Room、事件与局部指令

固定 Seed `61100–61104` 分别产生 6、7、8、9、10 房，并逐值确定：

| Seed | Warden Directive | 只读消费的既有 Director Rule |
|---:|---|---|
| 61100 | `Warden.PredictivePatrol` | `Rule.PredictionLock` |
| 61101 | `Warden.RouteForewarning` | `Rule.OptimalPath` |
| 61102 | `Warden.PreemptiveLockdown` | `Rule.DistanceCorrection` |
| 61103 | `Warden.RiskMarking` | `Rule.RiskReward` |
| 61104 | `Warden.TrapEscalation` | `Rule.RepetitionPenalty` |

只接受 `GetAppliedRules` 返回的有效唯一 HandleId、十二条白名单 RuleId 和 Level `1..5`，并用公开 RuntimeState 确认 Active/Degraded。未知、重复、Countered、错误 Rule 或不匹配 Handle 使用可见 neutral fallback；不得读取 Provider Response、Request、Validator 或 Director 私有状态。

每条路径覆盖 Combat、Event/Trap、Shop、Safe 和最终 Boss。候选按 PrimaryAssetId 排序；同 Seed 的长度、候选、选择权重、指令、fallback 和最终房完全一致。

四个固定 Event：

| Event | 固定 Choice 与 RiskPressure Delta |
|---|---|
| `Warden.TrapGrid` | `DisarmGrid -1`；`ForceCrossing +1` |
| `Warden.RouteWarning` | `FollowWarning -1`；`TestForecast 0`；`IgnoreWarning +1` |
| `Warden.EarlyLockdown` | `TakeDetour -1`；`BreakBlockade +1` |
| `Warden.FalseAlarm` | `VerifySignal 0`；`ExploitGap +1`；`WaitAndObserve -1` |

- RiskPressure 始终 Clamp `0..4`。
- Event 不修改关系、不保存、不发货币、不直接应用奖励。
- 路线约束只能由 Registry 中准确 `(EventId, ChoiceId)` 绑定派生，只能影响尚未选择的已知 Warden 候选。
- 约束若会移除全部候选，执行确定性 no-op 并发布 `Warden.RouteConstraintNoEligibleAlternative`；未知绑定直接拒绝。
- RiskProvisionTerminal 只复用既有三选一不可重掷 Offer；活动运行结束后所有 Reward Handle 按既有 Room 生命周期清理。

# 三种 Enemy 与 Boss

固定 Enemy：

| EnemyId | 底层 archetype | 边界 |
|---|---|---|
| `WardenForecastSentinel` | Ranged | 仅数据化属性、感知和既有远程 Attack |
| `WardenLockdownGuard` | Shield | 仅数据化属性、感知和既有护盾行为 |
| `WardenRiskMarker` | Melee | 仅数据化属性、感知和既有近战行为 |

三者只经 Warden Enemy Registry 的 PrimaryAssetId 生成，不新增 GameplayTag、StateTree、Ability、字符串 Spawn 或任意类输入。最终 Encounter 包含 Warden Boss 和三种变体；Room Completion 要求所有 Spawn 已完成死亡/清理并收到一次匹配的 Boss Completion。

`APRWardenBoss` 与 `UPRWardenBossComponent` 拥有以下阶段：

1. Health≤75%：Predictive Attack
   - 读取最近一个合法 P0 Skill 值，预警 1.0 秒。
   - 使用不同 P0 Skill 或既有 Dodge 反制；重复预测 Skill 时只经 `UPRCombatSubsystem::ApplyDamage` 造成一次固定 10 基础伤害。
2. Health≤50%：Platform Lockdown
   - 以 Boss 相对 X 坐标划分 Left/Center/Right，预警 1.25 秒并封锁 3.0 秒。
   - 玩家离开目标区域即反制；未离开只经 CombatSubsystem 造成一次固定 10 基础伤害。
   - 不生成或保存平台、碰撞体、地图 Actor 或关卡修改。
3. Health≤25%：Risk Mark
   - 初始层数 `Clamp(1 + RiskPressure, 1, 4)`，持续 4.0 秒。
   - 每个不同 P0 Skill 命中清除一层；到期按剩余层数每层 5 点基础伤害。

缺少玩家、CombatSubsystem、合法预测或计时环境时进入可见 degraded no-op。三阶段只进入一次、反制幂等、Boss Completion 只发布一次；所有伤害仍由 CombatSubsystem 权威验证，不直接写 AttributeSet。

# 律衡固定剧情

Warden Chapter DataAsset 只包含以下排序、固定本地 StoryBeat：

- `Story.Warden.Axiom.Base`：风险不是结论，只是尚未反证的预测。
- `Story.Warden.Axiom.LowProbability`：低概率不是零；预警值得验证，不值得服从。
- `Story.Warden.Axiom.ImperfectOptimum`：不完全最优仍可选择；我们先保留下一条路。

Story 投影只读取：

- Companion 的 Primary 与 Axiom Relationship 快照；
- Quest 的 Completed 与 entitlement 快照；
- Memory 的最新有界 Summary。

Registry/Profile 不可用时显示固定 unavailable；不得读取 Quest Evidence、原始墓园、Memory 私有分区、Dialogue 队列、Prompt 或 Provider。Story 不修改 Relationship、Quest、Memory、Progression、Save 或 Dialogue，不生成自由文本。
