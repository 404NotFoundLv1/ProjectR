# 版本关系与单版本边界

- Direct upstream：v0.5.2；Direct downstream：v0.6.1，随后为 v0.6.2。
- 唯一建议实现提交：`v0.6.0 Add chapter one Allocator content pack`。
- 本版本只有一份公共合同、一个完成门和一个功能提交；禁止子版本、子合同、检查点或中间功能提交。
- v0.4.0–v0.5.2 的 Director、Room/Reward、Account/RunState、Save A/B、Progression、Memory、RealityHub、Combat、Enemy 与 Boss 公共合同均为冻结上游。仅允许本合同明确列出的增量 Registry 接缝和 Schema 7 追加。

# 目标与非目标

一次完整交付第一章“配给官”：从 RealityHub 创建账号并进入网络，完成确定性的 6–10 房章节路径，经历事件和章节配给终端，击败具有资源锁定、奖励剥夺和价格审计机制的 Allocator Boss，经既有账号终止流程返回 RealityHub，并幂等获得首枚人类异常证明。

不实现 v0.6.1+ 章节、章节主线扩展、结局变量、正式货币/库存/交易/商店、经济、掉落、难度、后续 Boss/Enemy/Rule、真实网络、LLM、Provider、凭据、自由文本、任意内容生成或平台功能。

# 真实工程冲突与 E-035 兼容语义

- `UPRRoomSubsystem` 当前固定加载基础 Registry、排除 `Room.Type.Shop` 并按基础 8 Room/3 Encounter/4 Event/4 Policy/30 Reward 校验。本版本只增加 PrimaryAssetId Registry 配置接缝和派生章节 Registry；默认 Registry 行为不得变化。
- Enemy 基础 Registry 以五个冻结 GameplayTag 为白名单。本版本不增加 GameplayTag，而以独立 PrimaryAssetId/EnemyId 作为章节内容身份；三种变体和 Boss 只把既有 Melee/Shield/Ranged/AuditorBoss Tag 作为底层 archetype 分类。
- Director 仍只有十二个固定 Rule。本版本五条资源/商店“法令”是章节局部 `FName` 指令，只消费已验证 Applied Handle 并调整已知章节内容，不进入 Director Request/Response、Validator、Registry、RuntimeState 或执行器。
- `FPRRunSummary::BossId` 是冻结的 `FGameplayTag`，不能承载 `Allocator`。ChapterSubsystem 必须用冻结的 RunId/AccountId/Seed、RoomSequenceCompleted、`FPRPrototypeRunResult.BossId=Allocator` 和成功 AccountDeleted 建立关联；不得写入、伪造或依赖 RunSummary 的 BossId。
- Shop 仅表示既有三选一、不可重掷 Reward Offer 的“配给终端”，不产生货币、价格扣款、库存、购买记录或第二套结算。
- 所有 Room 只读复用 `/Game/ProjectR/Maps/L_Network_Prototype`；不创建、修改或保存地图。

# Chapter 权威与公共值合同

`UPRChapterSubsystem : UGameInstanceSubsystem` 是以下行为的唯一所有者：

- 当前 Chapter/Content Registry、冻结的 Run/Room/Boss 关联值；
- 当前章节局部指令与 `AllocationPressure`；
- Human Anomaly Proof 资格、Schema 7 事务、失败重试及发布；
- 只读章节快照、World 重绑和生命周期清理。

固定身份：

- Chapter PrimaryAssetId：`ProjectRChapter:DA_Chapter_Allocator`；
- ContentId：`Allocator`；
- BossId：`Allocator`；

- `EPRChapterLifecycleState`；
- `EPRChapterOperationResult`；

# Room、Reward 与 Enemy 增量接口

Room 只增加以下受控 C++ 接缝：

```cpp
EPRRoomContentResult ConfigureContentRegistry(FPrimaryAssetId RegistryId);
FPrimaryAssetId GetConfiguredContentRegistryId() const;
EPRRoomContentResult ConfigureContentContext(
    FName ContentId,
    FName ChapterDirectiveId,
    int32 AllocationPressure);
void GetAppliedRewardSnapshots(TArray<FPRAppliedRewardSnapshot>& OutRewards) const;
```

- 只能在 Idle、Completed 或 Cancelled 状态配置；活动序列中拒绝。
- RegistryId 必须由 AssetManager 解析为准确 Registry 类型并通过完整闭包校验；禁止对象路径、类或字符串加载入口。
- ContentId、DirectiveId 和 Pressure 必须由已配置 Registry 白名单验证；Pressure Clamp 为 `0..4`。
- `FPRAppliedRewardSnapshot` 只包含 RewardId、FamilyId、Tier 和规范 `FPRRewardEffectSpec`；不暴露 ASC、EffectHandle、SpecHandle、UObject 或 Widget。

Enemy 只增加：

```cpp
EPREnemyContentResult ConfigureContentRegistry(FPrimaryAssetId RegistryId);
FPrimaryAssetId GetConfiguredContentRegistryId() const;
EPREnemySpawnStatus SpawnEnemyPrototype(
    FPrimaryAssetId PrototypeId,

    APREnemyCharacter*& OutEnemy);
```

- 新 Registry 条目按 PrototypeId 排序、去重，且只引用具体 `UPREnemyPrototypeDataAsset` 和 `APREnemyCharacter` 子类。
- PrototypeId 是章节稳定身份；PrototypeDataAsset 的既有 PrototypeTag 只选择已冻结 archetype 行为。
- 现有 GameplayTag Spawn API、基础 Registry、五个原型及其行为保持不变。
- `FPREnemyRuntimeState` 只追加稳定 PrototypeId；运行时 Target、Actor、Timer、Delegate 和 Spawn Handle 不进入 Save。

# 确定性章节路径

- `DA_RoguelikeContentRegistry_Allocator` 必须闭合注册 10 个 Room、4 个 Encounter、4 个 Event、5 个 RewardPolicy、既有 30 个 RewardData、5 个章节指令及 Enemy/Boss 内容引用。
- 每轮路径为 6–10 房，候选首先按 PrimaryAssetId 排序，再以 Seed 和固定整数算法选择。
- 每条完整路径至少覆盖 Combat、Event、Shop、Safe，并以 `DA_Room_Allocator_Boss_Allocator` 结束。
- 五个固定 Seed `61000–61004` 分别选择五条章节指令；相同 Seed 的路径、候选、指令、Event 选择结果、Reward Offer 和 Spawn 顺序必须逐值相同。
- 未知、重复、未排序、越界或不闭合的 Room、Encounter、Event、Policy、Reward、Enemy、Boss、Directive 一律拒绝，不旅行、不 Spawn、不 Apply。
- Director 只允许通过 `GetAppliedRules`/只读 RuntimeState 提供的已验证 Handle 调整已知 Room 权重；不能读取原始 Provider Response 或私有状态。
- `Room.Type.Shop` 在本版本与 Safe 一样进入 Reward Offer，不启动 Encounter；仍必须生成三个不同、合法、不可重掷的选项。

# 四个事件与 AllocationPressure

四个事件只产生瞬态、可读的章节压力，不修改 Relationship、PlayerProfile、Progression、Memory、Quest 或 Save：

| EventId | 固定选择 | Pressure Delta |
|---|---|---:|
| `Allocator.ShortageAppeal` | `Share` / `Ration` / `Reject` | `-1 / 0 / +1` |
| `Allocator.MispricedLot` | `Report` / `Leave` / `Accept` | `-1 / 0 / +1` |
| `Allocator.ConfiscationNotice` | `Appeal` / `Comply` | `-1 / +1` |
| `Allocator.OverstockLedger` | `Redistribute` / `Reserve` | `-1 / +1` |

`AllocationPressure` 初始为 0，每次选择后 Clamp 到 `0..4`。重复 ResolutionId 不重复应用；旅行保持当前 Chapter 会话值，账号终止、Profile 切换、PIE Stop 或 Deinitialize 清零。

# 五条章节局部指令

固定白名单：

1. `Allocator.ResourceLock`
2. `Allocator.RewardWithholding`
3. `Allocator.PriceAudit`
4. `Allocator.ScarcityMarkup`
5. `Allocator.EqualizationQuota`

每轮只允许一条活动指令：

- ResourceLock：Shop 权重排除当前比例最高资源对应的恢复 Family。
- RewardWithholding：Epic Reward 权重按整数规则减半。
- PriceAudit：不修改 Offer；将实际选择的 Reward Tier 计入 Boss AuditUnits。
- ScarcityMarkup：某资源比例低于 35% 时，对应恢复 Family 权重减半。
- EqualizationQuota：为比例最低资源保证一个合格恢复选项；不存在合格项时使用中性确定性回退。

所有指令只能处理既有 30 个 RewardData、已知 Family 和规范 EffectSpec。无论指令如何调整，Offer 必须仍为三个互不冲突的选择；无法满足时使用基线确定性 Offer，不能创建未知奖励。指令状态、权重、审计计数和回退原因全部是会话值，结束时清理。

# 三种敌人变体

章节 Enemy Registry 固定三种变体：

- `AllocatorDebtCollector`：独立 EnemyId/PrototypeId，复用 `Enemy.Type.MeleeMinion` archetype、既有近战类、AbilitySet 和 AttackData。
- `AllocatorQuotaGuard`：独立 EnemyId/PrototypeId，复用 `Enemy.Type.ShieldMinion` archetype、护盾和既有 ShieldBreak 语义。
- `AllocatorPriceClerk`：独立 EnemyId/PrototypeId，复用 `Enemy.Type.RangedMinion` archetype、既有远程类和投射物。

不得创建新攻击类型、Ability、Damage、AttributeSet、StateTree、QTE 或 Companion AI 逻辑。Spawn 必须由 Encounter 的 PrototypeId 白名单驱动；未知 PrototypeId 不回退为字符串/类 Spawn。死亡、重复状态事件、Room 结束、旅行、EndPlay 和 PIE Stop 必须清理 Actor、Timer、Delegate、Target 和 SpawnId。

# Allocator Boss

`APRAllocatorBoss` 继承现有 Enemy 基础，`UPRAllocatorBossComponent` 是 Allocator 阶段、反制、临时 GE 和一次性 Completion 的唯一所有者。它不修改 `UPRBossSubsystem` 或 Auditor 状态机，只向既有 `PublishPrototypeRunCompleted` 发布 `FPRPrototypeRunResult`，其中 `BossId=Allocator`。

Boss Encounter 通过 Enemy PrimaryAssetId Registry 生成 Boss 和三种变体各一名。Room 只有在收到匹配 BossId/SpawnId 的一次性 Completion，且全部登记变体均死亡后才能完成。

三阶段固定为：

1. Health ≤75%：Resource Lock
   - 经既有 GAS Reward Application 路径应用可逆的 `MaxEnergy -25` 会话 Effect。
   - 玩家以两个不同的合法 `Skill.*` AbilityTag 造成伤害后解除。

2. Health ≤50%：Reward Deprivation
   - 从 `FPRAppliedRewardSnapshot` 选择 Tier 最高的会话 Reward；平级按 RewardId 字典序。
   - 通过同一 GAS 路径应用其规范 EffectSpec 的有界反向效果。
   - 玩家连续以三个不重复的合法 `Skill.*` AbilityTag 造成伤害后解除。
   - 没有可逆会话 Reward 时发布可读 degraded no-op，不伪造效果。

3. Health ≤25%：Price Audit
   - `AuditUnits = Clamp(所选 Reward Tier 总和 + AllocationPressure, 0, 12)`。
   - 通过 GAS 应用 `100 + 20 * AuditUnits` 的审计 Shield。
   - 只由现有正常伤害路径击破，不修改 Combat 或 AttributeSet 权威。

每个阈值只进入一次；重复 CombatEvent、状态回调或伤害 Tag 不重复推进。Defeat、房间取消、地图旅行、账号终止、EndPlay、PIE Stop 和 Deinitialize 必须移除准确 GameplayEffectHandle、Timer、Delegate、Actor/ASC 弱引用及反制样本。

# Human Anomaly Proof 与 Schema 7

`HumanAnomalyProof.Allocator` 是不可消费、Profile-local 的章节资格，不是 CounterproofFragments、MemoryFragments、货币或 Reward。

ChapterSubsystem 在成功 StartRun 后冻结公开 `FPRRunRuntimeState` 的 RunId、AccountId 和 Seed；随后只消费：

- 同一活动 Seed/Session 的 `FPRRoomSequenceCompleted`；
- `BossId=Allocator` 且匹配登记 SpawnId 的 `FPRPrototypeRunResult`；
- 最终成功发布、RunId/AccountId/Seed 一致且 TerminationReason 为 RoomSequenceCompleted 的 `FPRAccountDeletedEvent`。

证明资格要求 CompletedPath 全部属于 Allocator Registry、最后房为 Allocator Boss、Boss Completion 已确认。不得读取或写入 `FPRRunSummary::BossId`，也不得修改 RunState/Account 的完成、CounterproofFragment 或 RealityHub 旅行语义。

Schema 6→7 只追加：

```text
FPRChapterPersistenceData
  CompletedChapterIds: 最多 5 个排序、去重的 FPrimaryAssetId
  HumanAnomalyProofIds: 最多 5 个排序、去重的 FName
  SettlementSequence: int64
```

迁移严格为 `1→2→3→4→5→6→7`。6→7 使用空安全默认，不回溯旧 Graveyard、不补发证明。保持 PRSV A/B、较新有效代选择、损坏恢复、未来版本拒绝、旧客户端不覆盖、写前冲突、写后回读及真实用户存档隔离。

SaveSubsystem 只为 `UPRChapterSubsystem` 增加 friend 可调用的 `GetChapterPersistenceSnapshot` 和 Expected/Target `StageChapterPersistenceTransaction`；不提供 Blueprint 或公共任意写入口。只有 A/B 写后回读成功后才发布 `FPRChapterCompletionResult` 和 Proof；失败进入 `ReadyToRetry`，无参数重试同一冻结事务。

死亡、DivergenceEvacuation、DivergenceLeave、InterruptedRecovery、非法路径、Boss 未完成、重复 RecordId 或已经持有 Proof 时不增加 Proof 或 SettlementSequence。账号已经成功终止但证明保存失败时，在 RealityHub 保留冻结事务；Profile 重新加载后只允许从公开、有界 Graveyard Snapshot 恢复尚未结算的合格当前 Schema-7 记录。ChapterSubsystem 不调用 OpenMap。

# 生命周期与 RealityHub 闭环

- Profile Load/Create 后配置固定 Allocator Chapter/Room/Enemy Registry；Registry 不可用时 StartRun 仍由既有入口返回明确失败，不使用未知 fallback。
- 现有 RealityHub 卡带槽继续调用既有 RunState 创建账号和 StartRun；不修改 RealityHubSubsystem 或 Widget Package。
- 普通地图旅行保留 GameInstance 章节会话值，并在新 World 幂等重绑 Room、Boss、Enemy 和 Combat 的公开 Delegate。
- 账号终止后先由 RunState 完成既有 A/B 账号事务、发布 AccountDeleted 并返回 RealityHub；Chapter 再完成独立 Schema-7 证明事务。
- Profile 切换、World cleanup、账号失败/中断、PIE Stop 与 Deinitialize 必须解除 Delegate、停止 Timer、移除 Widget、取消冻结上下文并清理所有章节创建的 GE/Actor/Handle。
- Overlay 只显示 Chapter、Room、Directive、Pressure、Boss 阶段/反制、Settlement 状态和 Proof 结果，不承担路径生成、奖励应用、Boss 判定或持久化。
