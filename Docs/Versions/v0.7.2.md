# 目标与非目标

# E-040 最小兼容语义

- “账号不死”是叙事名称：账号仍由 `UPRRunStateSubsystem` 完成既有 `AccountDeleted` 与墓园事务，只有一个有界技能记忆跨账号存续。TripleResonance 不调用账号创建、删除、终止或物理槽操作。
- Schema-7 五个 Chapter/Proof 槽保持不变。Schema 8 新增独立 `FPRTripleResonancePersistenceData`；`HumanAnomalyProof.TripleResonanceHighRisk` 不进入 Chapter 集合、不参与章节选择。
- 十二项 P0 QTE Registry 的 ID、顺序、候选、冷却与行为保持不变。QTE 只增加三个编译期白名单的外部 TripleResonance ID，不接受任意 DataAsset、类、路径或字符串。
- GameplayTag 只增量追加 `Skill.TripleResonance` 与 `Cooldown.Skill.TripleResonance`；不增加 InputTag，启动和第三步均复用既有 `Input.Execute`。
- Headmind 只增加一次性、精确身份校验的 TripleResonance 结果接收接缝；不修改 Demo Auditor 的 P1–P3、PredictionShield、Combat mitigation、BossSubsystem 或唯一 Completion。

# 权威所有者与公共值合同

新增 `UPRTripleResonanceSubsystem : UGameInstanceSubsystem`，唯一拥有：

- 资格与 Run/Account/Boss/窗口值冻结；
- 固定三步 QTE 编排和结果去重；
- 瞬态 Ability Grant、执行、冷却和移除；
- 蛇怪反制结果；
- Schema 8 Legacy/高风险 Proof 事务与失败重试；
- 跨 World 重绑、只读快照、展示投影和生命周期。

状态机固定为：

`Unavailable → Ready → QTEActive → AbilityPending → Executing → Resolved`

资格丢失、拒绝、错误、超时、依赖缺失、窗口关闭或 Ability 失败进入 `Failed`；持久化失败进入 `ReadyToRetry`。同一冻结 Run/Account/Boss/窗口最多触发一次。

新增值类型：

- `EPRTripleResonanceState`
- `EPRTripleResonanceOperationResult`
- `EPRTripleResonanceStep`

- `FPRTripleResonanceSnapshot`
- `FPRTripleResonanceExecutionResult`
- `FPRSkillMemoryFragment`

公共 C++ API 仅允许：

bool GetSnapshot(FPRTripleResonanceSnapshot& OutSnapshot) const;

不提供 Blueprint 写 API、任意 Profile/Slot/Account/Run/Boss/QTE/Ability/Tag/Class/Object/Path/JSON 输入、余额修改、强制触发、强制成功或运行时 Registry setter。

# 精确资格与冻结身份

资格只在 Headmind 蛇怪窗口开启时冻结，必须同时满足：

1. `FPRTripleResonanceOpportunitySnapshot.State == EligibleDeferredToV072` 且 `bWindowActive=true`；
2. `TripleResonance.ChapterPrerequisite.Auditor` 有效；
3. StartRun 冻结的 Progression entitlement 含 `ProgressionNode:BondTripleResonance`，不得使用运行中后来解锁的值；
4. Axiom、Kindle、Null 三项规范关系快照均为 Trust≥70、Overload=0；
5. 活动 Chapter 为 Headmind，且冻结 RunId、AccountId、Boss SpawnId、World 与当前公共运行值精确匹配；
6. 当前账号、Boss 和窗口尚未触发或结束 TripleResonance；
7. 玩家 Pawn、ASC、QTE、Combat 与精确 Headmind Boss 均可用。

未知、重复、迟到、错误 World、错误 Boss、错误 SpawnId、错误 Run/Account、Profile 切换后的值或已经结束的窗口全部拒绝，不产生资源、伤害、冷却、QTE、保存或 Completion。

# 固定三步 QTE

玩家只在 `Ready` 状态按既有 `Input.Execute` 启动。QTE 必须在 Headmind 现有五秒蛇怪窗口内按固定顺序执行：

1. Axiom：1.25 秒，接受 `Input.Interact`；
2. Kindle：1.25 秒，接受 `Input.Attack`；
3. Null：1.25 秒，接受 `Input.Execute`。

固定外部 QTE ID：

- `QTE:TripleResonance_Axiom`
- `QTE:TripleResonance_Kindle`
- `QTE:TripleResonance_Null`

Companion 分别固定为 `Companion.Axiom`、`Companion.Kindle`、`Companion.Null`；类型分别复用 `QTE.Type.RuleCounter`、`QTE.Type.Attack`、`QTE.Type.Control`。`Input.QTE.Reject`、错误输入、超时、窗口关闭、Pawn/World 更换、死亡或任何一步取消均终止整条链。

三个外部 QTE：

- 不进入十二项 P0 Registry 或全局候选排序；
- 只由 TripleResonanceSubsystem 的冻结请求调用；
- 使用新增枚举末尾的 `ResultOnly` 效果，不直接造成伤害、GE、位移、关系或画像变化；
- `RelationshipDelta` 全部为 0；
- 仍由 `UPRQTESubsystem` 拥有请求、Prompt、计时、输入、结果和清理；
- 结果重复、迟到或 RequestId 不匹配时丢弃。

# Ability、资源、冷却、伤害与处决

三步全部成功后：

1. 固定 Charge GE 将 Resonance 补充到可支付的 100；
2. Authority 向当前 Player ASC 瞬态授予 `UPRGA_TripleResonance`；
3. Ability Commit 通过固定 Cost GE 消耗 100 Resonance；
4. Commit 成功后施加 90 秒固定 Cooldown GE；
5. 目标只能是冻结的 `APRHeadmindProjectionBoss` 与 SpawnId；
6. Headmind 固定接缝将当前蛇怪窗口标记为已反制、停止其 Timer 并关闭机会值；
7. Ability 通过 `UPRCombatSubsystem::ApplyDamage` 发布一次 `Skill.TripleResonance` 请求。

数值固定为：

- 常规基础伤害：120；
- 处决阈值：结算前 Health/MaxHealth≤20%；
- 处决仍提交足以覆盖当前合法 Health/Shield 的单次 Combat 请求，不直接写 Attribute、Dead Tag 或 Boss 状态；
- 只允许一次 Combat 结果和一次 `FPRTripleResonanceExecutionResult`。

PredictionShield 继续按既有规则只阻断其预测的 P0 `Skill.*`；TripleResonance 使用独立精确 Tag，不改写或清空 Demo Auditor 状态。Boss 死亡与 Completion 继续完全由既有 Combat、Demo Auditor和 BossSubsystem 发布；本系统不得发布第二次 Completion。

Cost、Cooldown、Combat、QTE、ASC、Headmind 或精确目标缺失时执行可见 degraded no-op。Ability 未 Commit 时不得消耗 Resonance或建立冷却；失败/取消必须移除临时 Spec 与本系统创建的瞬态 GE。

# Schema 8 与有界持久化

Schema 8 只追加 `FPRTripleResonancePersistenceData`：

- `LastProcessedGraveyardOrdinal`
- 最多一个 `FPRSkillMemoryFragment`
- 最多一个固定 `HumanAnomalyProof.TripleResonanceHighRisk`
- `LegacySequence`
- `HighRiskProofSequence`

`FPRSkillMemoryFragment` 只包含：

- `SourceSummaryId`（对应 `FPRAccountRecord.RecordId`）
- 六项 P0 中一个 `AbilityTag`
- 来源 `GraveyardOrdinal`
- `LegacySequence`

不得保存 ProfileId、Slot、ActiveAccount、AbilitySpec、GE/Spec Handle、Actor、ASC、QTE Runtime、Boss Runtime、Widget、Timer、Delegate、弱引用、动态 Registry 或原始事件。

迁移严格为：

`1 → 2 → 3 → 4 → 5 → 6 → 7 → 8`

7→8 默认分区为空，并把 `LastProcessedGraveyardOrdinal` 初始化为现有 Graveyard 最大序号；禁止从旧墓园回溯生成技能记忆、Proof 或序列。继续保持 PRSV A/B、较新有效代选择、损坏恢复、未来版本拒绝、旧客户端不覆盖、写后回读、失败不发布和冻结事务重试。

# 技能记忆与高风险 Proof

只有成功发布的 `FPRAccountDeletedEvent` 才可启动 Legacy 事务，并必须同时满足：

- 终止原因为 `RoomSequenceCompleted`；
- Record/Summary 的 SummaryId、RunId、AccountId 与冻结 TripleResonance 结果一致；
- Headmind Room Sequence、最终 Room、Boss Completion 与 TripleResonance 蛇怪反制均成功；
- 冻结 `SynthesisPressure == 4`；
- `FPRRunSummary.MinimumHealthRatio <= 0.25`；
- GraveyardOrdinal 大于迁移水位且从未处理；
- `SkillSummaries` 中至少一个六项 P0 Skill 有成功 Commit。

技能记忆选择固定为：

1. 排除 `Skill.BasicAttack` 与 `Skill.TripleResonance`；
2. 只接受六项发布的 P0 Skill；
3. 按 `CommitCount` 降序；
4. 再按 `UseCount` 降序；
5. 再按 AbilityTag 字典序；
6. 取唯一第一项。

首次有效 SummaryId 在同一 Schema-8 A/B 快照中保存技能记忆和 `HumanAnomalyProof.TripleResonanceHighRisk`。成功回读前不发布 Legacy、Proof 或操作成功；失败进入 `ReadyToRetry`，只重试相同冻结事务。

已持有高风险 Proof、重复事件、重复回调、重复重试、重玩、死亡、撤离、中断、错误路径/Boss/身份、无有效 Skill 或迁移旧档均不更新、不增加序列、不补发。

下一次成功 StartRun 只冻结并公开 `FPRTripleResonanceLegacySnapshot`；v0.7.2 不修改六项 Ability、AbilitySet、Reward、Progression余额或当前构筑。v0.8.0 才能通过自己的插件池事务消费该技能记忆。
