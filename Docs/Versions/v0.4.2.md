# 所有权与数据流

`UPRRoomSubsystem : UGameInstanceSubsystem` 是会话房间流程的唯一所有者：

```text
Validated Content Registry
        ↓
Deterministic Room Path
        ↓
Validated LevelAsset / EncounterId
        ↓
CombatEvent / Boss Completion / Event Choice
        ↓
Three-choice Reward Offer
        ↓
IPRRewardApplication
        ↓
Session Reward Handle / Completion Result
```

- 普通地图旅行保持房间序列和奖励记录，并在新 PlayerState/ASC 上幂等重绑持续奖励。
- 完成、取消或 Deinitialize 时准确清除 Reward GE、Timer、Delegate、Spawn 记录和 UI。
- RuntimeState 只含值类型、稳定 ID 和 GameplayTag；不得包含 UObject、ASC、ActiveEffectHandle、Timer 或 Delegate。
- Director 只通过 `GetAppliedRules` 和 `GetRuleRuntimeStates` 提供已验证的稳定值。
- 未知 Room、Encounter、Reward、Rule、LevelAsset 或 Registry 外 Enemy 必须拒绝，不能回退到任意类、对象路径或字符串 Spawn。

# 公共 C++ API

```text
EPRRoomOperationResult StartRoomSequence(int32 Seed, FGuid& OutSessionId)
EPRRoomOperationResult SelectRoom(FPrimaryAssetId RoomId)
EPRRoomOperationResult SelectEventChoice(FName ChoiceId)
EPRRoomOperationResult ConfirmSafeRoomExit()
EPRRoomOperationResult SelectReward(
    FPrimaryAssetId RewardId,
    FGuid& OutHandleId)

bool GetRoomRuntimeState(FPRRoomRuntimeState& OutState) const
void GetAppliedRewards(
    TArray<FPRRewardApplicationHandle>& OutHandles) const

FPRRoomStateChangedNative& OnRoomStateChanged()
FPRRewardOfferChangedNative& OnRewardOfferChanged()
FPRRoomEventResolvedNative& OnRoomEventResolved()
FPRRoomSequenceCompletedNative& OnRoomSequenceCompleted()
```

- 所有入口仅接受当前 RuntimeState 已发布的候选。
- Completion、Reward selection 和 Event choice 各只能结算一次。
- Reward Handle 只接受 Subsystem 内部准确记录；伪造或重复移除返回 NotFound，不能影响其他奖励。
- UI 只调用受控选择 API；核心生成、条件、奖励和完成逻辑不进入 Widget。

# 路径与 Encounter 合同

- 路径长度为 `6 + Hash(Seed) % 5`，即 6–10。
- 最后一房固定 Boss；Boss 不得提前出现。
- 每一步最多发布两个合法候选；候选先按稳定 ID 排序，再使用 Seed 做确定性选择。
- 路径至少包含 Combat、Event 与 Safe 候选；不能连续选择同一 RoomId。
- Director Applied Rule/RuntimeState 只能改变 Registry 内已知候选与奖励的权重，不能生成 Registry 外内容。
- `Room.Type.Shop` 不进入默认 Registry或路径。
- Level travel 只能使用 RoomData 中已验证的 `LevelAsset`；不得接受调用方路径。
- CombatStandard 使用既有 Enemy Registry 白名单生成普通遭遇。
- EliteAudit 使用既有精英原型，不创建新 Enemy 类型。
- BossAuditor 使用既有 Auditor Boss 和 Completion 事件。
- Encounter 的伤害、死亡与 CombatEvent 仍只由 `UPRCombatSubsystem` 产生。
- Enemy/Boss 完成只按稳定 SpawnId、EncounterId 和事件 ID 消费一次。
- Encounter 结束后停止攻击并清理本房生成记录；旅行与取消不能留下 Actor、Timer 或 Delegate。

# 事件房合同

四个稳定 Event Room：

- Ethics：Observe 无变化；Cooperate 为 `Trust +2`、`Evaluation +1`；Defy 为 `Affection +2`、`Evaluation -1`。
- MemoryCorridor：Pass 无变化；Preserve 为 `Affection +2`；Archive 为 `Evaluation +2`、`Overload -2`。
- CurseProtocol：Refuse 无变化；Accept 为 `Overload +5`，并仅提高当前 Reward Offer 的 Epic 权重。
- Commission：Decline 无变化；Fulfill 仅在最近有效 QTE 为 Success 时可用，并应用 `Trust +2`、`Evaluation +2`。

关系变化只调用既有 `UPRCompanionSubsystem::ApplyRelationshipDelta`；PlayerProfile 通过既有 Relationship 事件自然采样，不新增画像写入口。没有加载 Profile 时，所有带关系 Delta 的选项不可用；每个事件必须保留至少一个无 Delta 选项。事件不得直接请求 Save。

# Reward 合同

- 每次清房从当前 RewardPolicy 无放回选择准确三项。
- 相同 Seed、路径、已选 Reward 和 Director Runtime 必须产生逐字段相同的 Offer。
- 同一 Family 只保留最高已选 Tier；高 Tier 原子替换低 Tier，同级或低级不再 eligible。
- 持续效果通过 GAS 会话 GE 应用；瞬时资源效果也通过 GAS，不直接写 `UPRAttributeSet`。
- 所有奖励在会话结束时清理，不进入 Save。
- Rarity Tier 固定为 Common、Rare、Epic。

固定 30 项 RewardData：

| Family | Common / Rare / Epic |
|---|---|
| VitalityCache | MaxHealth +10 / +20 / +30 |
| ShieldCache | MaxShield +5 / +10 / +15 |
| EnergyCache | MaxEnergy +5 / +10 / +15 |
| AttackCache | AttackPower +1 / +2 / +3 |
| MobilityCache | MoveSpeed +15 / +30 / +45 |
| PrecisionCache | CritChance +0.01 / +0.02 / +0.03 |
| HealthRepair | Health 恢复 20 / 35 / 50 |
| ShieldRepair | Shield 恢复 10 / 20 / 30 |
| EnergyRefill | Energy 恢复 15 / 25 / 40 |
| ResonancePulse | Resonance +10 / +20 / +30 |

不修改既有基础数值；属性继续由 AttributeSet 既有 Clamp 处理。
