# 权威所有者与输入边界

`UPRMemorySubsystem : UGameInstanceSubsystem` 是以下行为的唯一所有者：

- 当前运行的有界关键事实聚合；
- Memory Registry、Persona Registry 与摘要构建；
- 局后 Provider 请求、Validator、Mock、fallback、去重和超时；
- Schema 6 Memory 分区事务及失败重试；
- MemoryFragments 来源资格与单枚入账请求；
- 只读快照、World 重绑和完整生命周期清理。

只允许消费以下既有公共值：

- `FPRAccountDeletedEvent.Record.Summary` 与 `FPRAccountRecord.RecordId/GraveyardOrdinal`；
- `FPRRoomEventResult`、`FPRDialogueResult`、`FPRDivergenceResult`；
- Companion Quest 的 Completed 快照、固定 entitlement 与 LineId；
- SaveSubsystem 和 ProgressionSubsystem 的受控 C++ API。

不得读取 Quest Evidence、墓园原始持久化数组、Dialogue 队列、Director 私有状态、原始 Provider Response、Profile/Account/Slot 私有数据或真实用户存档。现有 `FPRRunSummary` 继续由 RunState 所有；本版本不创建第二套 RunSummary、不修改 `UPRRunStateSubsystem`，只从成功发布的账号终止事实派生有界 `FPRMemorySummary`。

# 有界 MemorySummary

每条摘要以 `FPRAccountRecord.RecordId` 作为幂等 `SummaryId`，最多包含：

- 一个结束原因与受限死因语义；
- 12 个已验证 Director Rule ID；
- 16 个 QTE 聚合 ID；
- 8 个 Room/Dialogue/Divergence `FPRMemoryChoiceRef`；
- 6 个 Completed QuestId；
- 16 个去重、排序的 KeyEventId；
- 一个固定 CompanionId、SceneId、EmotionId；
- 最多 240 个 Unicode code point 的摘要文本；
- 恰好 3 个固定 PlayerOptionId；
- fallback 标记、摘要序列、GraveyardOrdinal 与本摘要碎片奖励值。

摘要不得保存 AccountId、ProfileId、Slot、无限原文、原始事件流、对话日志、Prompt、原始响应、UObject、Actor、Timer、Delegate、Widget、Provider、Handle 或弱引用。最多保存 32 条摘要，按 `GraveyardOrdinal + SummaryId` 严格排序；所有数组必须去重、规范化并拒绝未知 ID。10 轮及更长期运行不得产生无界增长。

关键事实只在当前 GameInstance 中有界聚合；`FPRAccountDeletedEvent` 到达时才冻结。摘要构建不得反查墓园或其他上游私有容器，也不得把未验证的实时事件直接持久化。

# Save Schema 5→6

新增 `FPRMemoryPersistenceData`，作为 `UPRSaveGame` 的唯一 Schema 6 追加分区：

- 最多 32 条规范化摘要；
- `LastProcessedGraveyardOrdinal`；
- `LifetimeSummaryCount`；
- `LifetimeMemoryFragmentsAwarded`；
- `SummarySequence`。

迁移必须严格为：

`1 → 2 → 3 → 4 → 5 → 6`

5→6 默认 Memory 列表为空，并把 `LastProcessedGraveyardOrdinal` 初始化为现有 Graveyard 的最大序号；不得在迁移时重新总结旧账号或补发货币。保持 PRSV A/B、较新有效代选择、损坏恢复、未来版本拒绝、旧客户端不覆盖未来数据、写前冲突、写后回读验证、失败不发布和冻结事务重试语义。

SaveSubsystem 只持有规范值，不依赖 Memory 运行时类型。Memory 与 Progression 的完整规范分区必须在同一个 A/B Profile 快照中原子暂存、写入并回读；任一分区非法或写后验证失败时，内存快照、摘要事件和余额事件都不得发布。测试只使用隔离 automation Profile/Storage，禁止读取、写入、迁移或删除真实用户存档。

# MemoryFragments 最小来源

每个 SummaryId 只有在以下条件全部成立时固定奖励 1 个 MemoryFragment：

- 首次处理；
- Memory + Progression 原子事务成功落盘并回读；
- 结束原因不是 `InterruptedRecovery`；
- 至少包含一个合法 KeyEventId；
- `GraveyardOrdinal` 大于已处理水位。

空摘要、`InterruptedRecovery`、无效/超界数据、重复事件、重复回调、重复重试、已存在 SummaryId 或已处理 GraveyardOrdinal 的奖励均为 0。

Progression 继续是余额唯一所有者。只允许为 `UPRMemorySubsystem` 增加 friend 可调用的私有单枚入账投影；不提供 Blueprint 或公共余额修改 API，不接受任意数值。不得修改 `UnlockSequence`、当前活跃 `FPRProgressionRunSnapshot`、节点、价格、消费、CounterproofFragments、经济或奖励业务。相同冻结事务的失败重试必须保持同一 SummaryId、SummarySequence 候选和奖励值，成功后重复回调幂等无操作。

# Provider、Validator 与安全 Schema

新增内部 `IPRPostRunDialogueProvider`、`FPRPostRunDialogueValidator` 与确定性本地 Mock。默认不创建 HTTP Provider、Transport、端点、API Key、远程模型或客户端凭据。实时战斗、QTE、伤害、房间和法令执行永不等待 Provider。

Provider 候选只允许以下五字段：

```json
{
  "scene": "post_run_summary",
  "companion_id": "Axiom | Kindle | Null",
  "emotion": "<fixed persona emotion>",
  "summary": "<bounded summary>",
  "player_options": ["<fixed id>", "<fixed id>", "<fixed id>"]
}
```

Validator 固定规则：

- `additionalProperties=false`，五字段全部必需；
- `scene` 只能是 `post_run_summary`；
- `companion_id` 只能是 Axiom、Kindle、Null，且必须匹配请求；
- emotion 白名单：
  - Axiom：`analytical`、`concerned`、`quietly_proud`；
  - Kindle：`fired_up`、`frustrated`、`relieved`；
  - Null：`sarcastic`、`sarcastic_worried`、`sincere`；
- summary 长度为 1–240 个 Unicode code point；控制字符、双向覆盖字符、URL、HTML/JSON 标记、Prompt/角色指令、凭据及 Profile/Account/Slot 标识词整份拒绝；
- `player_options` 必须恰好三项、去重、顺序稳定，并来自相同 Persona Registry：
  - Axiom：`axiom_reflect`、`axiom_challenge`、`axiom_deflect`；
  - Kindle：`kindle_steady`、`kindle_critique`、`kindle_thank`；
  - Null：`null_promise`、`null_callout`、`null_analyze`；
- 选项显示文本只来自本地 Persona DataAsset；
- `memory_refs`、关系 Delta、Tag、效果、系统指令、数值和任何未知字段整份拒绝；
- Provider 输出不允许数值字段；请求侧将 Duration Clamp 到 `0..86400`、DeathCount Clamp 到 `0..99`、RuleLevel Clamp 到 `1..5`、QTE Count Clamp 到 `1..999`；
- 超时固定 1 秒；第一个匹配 RequestId 的有效响应终结请求；
- 重复、迟到、错误 RequestId、Profile 切换后或已取消请求的响应全部丢弃；
- unavailable、timeout、非法结果立即使用确定性本地 fallback，不进入重试风暴。

Mock 只使用 `SummaryId + CompanionId + 排序后的 KeyEventIds` 的稳定哈希选择固定 emotion、摘要模板和三个选项；不得使用随机时间、网络、自由 Prompt、原始事件、存档私有数据或用户自由文本。Provider 原始候选仅存在于 Validator 调用栈，不记录到日志、Save、快照或 Widget。

# 生命周期

- AccountDeleted 成功发布后才冻结摘要并发起 Provider；同一 SummaryId 只允许一个活动请求和一个持久化事务。
- 普通地图旅行保留 GameInstance 的冻结事务，并在新 World 幂等重绑公开上游 delegate；重复绑定不得重复聚合、保存或发放碎片。
- 保存失败进入 `ReadyToRetry`，只允许无参数 API 重试同一冻结事务；不得重新生成摘要、重新调用 Provider 或改变候选奖励。
- Profile Load/Create、Profile 切换、World cleanup、PIE Stop 与 Deinitialize 必须取消准确 Provider 请求、Ticker/Timer、Delegate、Widget 和迟到回调，清空瞬态聚合并恢复安全状态。
- Widget 销毁或旅行不取消已经冻结的 Save 事务，但必须移除自身绑定；Subsystem Deinitialize 必须拒绝新请求并清理所有运行时句柄。
