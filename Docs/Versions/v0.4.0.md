# 目标

- 建立有界、只读、跨普通地图旅行保持的 PlayerProfile。
- 建立 `DirectorRuleDataAsset`、固定本地 Registry、`DirectorSubsystem` 和运行时 Applied Rule Handle。
- 实现确定性 Mock Provider、可替换的 Provider 接口、默认不联网的 HTTP Provider/Transport 边界。
- 冻结以下唯一数据流：

```text
FPRPlayerProfileSnapshot
  -> FPRDirectorRequest
  -> IPRDirectorProvider
  -> FPRDirectorResponse
  -> UPRDirectorResponseValidator
  -> Local Rule Registry
  -> FPRAppliedDirectorRuleHandle
```

- 所有 Provider 输出必须先经过 Schema、RequestId、白名单、Clamp、长度、超时和 fallback 验证；未知 RuleId 永远不能进入 Applied Rule 层。
- 无网络、Provider 不可用、超时或响应非法时，系统仍能以本地确定性 Mock 完成相同流程。

# PlayerProfile 公共合同

## 所有权与生命周期

`UPRPlayerProfileSubsystem : UGameInstanceSubsystem` 是 PlayerProfile 的唯一运行时所有者。

- 成功 Create/Load Profile 开始新的画像运行会话并重置旧画像。
- 普通地图旅行、Pawn 替换和 World 重建不重置画像。
- Deinitialize 清除全部绑定、去重缓存和运行时数据。
- v0.4.0 不创建正式 RunState；v0.4.3 可以替换“新画像会话”信号，但不得改变 Snapshot Schema 的既有字段语义。
- Subsystem 只订阅既有公共值事件和只读状态，不向上游系统发出业务命令。

允许的稳定输入：

- `FPRCombatEvent`
- `FPRAbilityLifecycleEvent`
- `FPRQTEResult`
- `FPRRelationshipChangedEvent`
- `FPRPrimaryCompanionSyncChangedEvent`
- `FPRDivergenceResult`
- `APRPlayerState` 的只读属性变化事件
- Save Operation 的成功 Create/Load 会话信号

`FPRCombatEvent` 中的 Actor 弱引用只允许在回调瞬间用于计算有限 X/Z 距离；不能被保存、转发或写入 Snapshot。其他消费者类型、私有队列、Actor、ASC、Timer、Delegate 和 UObject 不得进入画像。

## 固定值类型

`FPRPlayerProfileTaggedCount`：

- `FGameplayTag Tag`
- `int32 Count`

`FPRPlayerProfileSkillMetric`：

- `FGameplayTag SkillTag`
- `int32 UseCount`
- `int32 CommitCount`
- `int32 FailureCount`

`FPRPlayerProfileDistanceMetric`：

- `int32 SampleCount`
- `float MinimumDistanceCm`
- `float MaximumDistanceCm`
- `float AverageDistanceCm`

`FPRPlayerProfileResourceMetric`：

- `float DamageDealt`
- `float DamageTaken`
- `float ShieldAbsorbed`
- `float EnergySpent`
- `float MinimumHealthRatio`

`FPRPlayerProfileDivergenceSummary`：

- `FGuid ResultId`
- `FGameplayTag CompanionId`
- `EPRDivergenceChoice Choice`
- `EPRDivergenceResolution Resolution`
- `EPRDivergenceFutureDisposition FutureDisposition`

`FPRPlayerProfileSnapshot`：

- `int32 SchemaVersion = 1`
- `FGuid SnapshotId`
- `FGuid ProfileSessionId`
- `int64 Sequence`
- `TArray<FPRPlayerProfileSkillMetric> SkillMetrics`
- `FPRPlayerProfileDistanceMetric CombatDistance`
- `TArray<FPRPlayerProfileTaggedCount> QTEResultCounts`
- `TArray<FPRPlayerProfileTaggedCount> QTEProfileSampleCounts`
- `int32 QTEPerfectTimingCount`
- `int32 DeathCount`
- `FPRPlayerProfileResourceMetric Resources`
- `FGameplayTag PrimaryCompanionId`
- `TArray<FPRCompanionRelationshipRecord> Relationships`
- `FPRPlayerProfileDivergenceSummary LastDivergence`
- `TArray<FPRPlayerProfileTaggedCount> RuleCounterCounts`
- `double WorldTimeSeconds`

边界：

- Skill、QTE ProfileSample 和 RuleCounter 数组分别最多 16 项。
- Relationships 只能包含 Registry 中三名已知 Companion，按 CompanionId 字典序输出。
- 所有数组按 GameplayTag 或稳定 ID 排序；Snapshot 不依赖事件到达的容器顺序。
- 计数只接受非负值并执行饱和累加；浮点数必须 finite，并按对应属性/距离合同 Clamp。
- EventId、ResultId 只消费一次。去重缓存最多保存最近 256 个 ID，按到达顺序淘汰；画像只保留累计值，不保留原始事件日志。
- SnapshotId 在每次生成快照时更新，ProfileSessionId 只在开始新画像会话时更新，Sequence 严格递增。

公共 API：

```text
bool GetSnapshot(FPRPlayerProfileSnapshot& OutSnapshot) const
FPRPlayerProfileChangedNative& OnPlayerProfileChanged()
```

- API 是只读 C++ 数据面，不开放 Blueprint 写入、任意样本注入或事件伪造。
- 测试注入只能存在于 `WITH_DEV_AUTOMATION_TESTS`，不得进入 Shipping 或正式调用面。

# Director 数据与 Provider 合同

## 公共枚举和结构

`EPRDirectorRequestStatus`：

- `Started`
- `Busy`
- `Invalid`
- `ProviderUnavailable`
- `ShuttingDown`

`EPRDirectorEvaluationResult`：

- `Applied`
- `FallbackApplied`
- `RejectedSchema`
- `RejectedRequestId`
- `RejectedUnknownRule`
- `RejectedReasonTags`
- `RejectedParameters`
- `RejectedText`
- `TimedOut`
- `Cancelled`

`EPRDirectorRuleOperationResult`：

- `Applied`
- `AlreadyApplied`
- `Replaced`
- `Removed`
- `NotFound`
- `Invalid`

`FPRDirectorNumericParameter`：

- `FName Name`
- `float Value`

`FPRDirectorRequest`：

- `int32 SchemaVersion = 1`
- `FGuid RequestId`
- `FPRPlayerProfileSnapshot Profile`
- `TArray<FGameplayTag> CandidateRuleIds`
- `int64 RequestSequence`
- `float TimeoutSeconds = 0.5f`

规则：

- TimeoutSeconds 合法范围固定为 0.05–2.0 秒。
- CandidateRuleIds 必须由本地 Registry 生成并按 Tag 字典序排列；外部调用者不得传入任意候选 Tag。
- 同一 DirectorSubsystem 只允许一个 in-flight Request；Busy 不创建第二请求。

`FPRDirectorResponse` 仅包含：

- `int32 SchemaVersion = 1`
- `FGuid RequestId`
- `FGameplayTag RuleId`
- `int32 Level`
- `FGameplayTagContainer ReasonTags`
- `TArray<FPRDirectorNumericParameter> Parameters`
- `FString VisibleReason`
- `FString ExpressionText`

`FPRAppliedDirectorRuleHandle`：

- `FGuid HandleId`
- `FGameplayTag RuleId`
- `int32 Level`
- `TArray<FPRDirectorNumericParameter> Parameters`
- `int64 ApplySequence`

Applied Handle 只表示经过验证的运行时激活记录，不复制、不保存，也不代表 GameplayEffect、Combat、Room、Reward 或资源效果已经执行。

## Provider 接口

`IPRDirectorProvider`：

```text
FName GetProviderId() const
bool IsAvailable() const
void RequestRule(
    const FPRDirectorRequest& Request,
    FPRDirectorProviderCompletion Completion)
void CancelRequest(FGuid RequestId)
```

- 所有 Completion 必须回到 Game Thread。
- Provider 不能直接访问 Registry 私有对象、创建 Handle或修改游戏状态。
- 迟到、重复、错误 RequestId 或 Subsystem 已 Deinitialize 的 Completion 必须丢弃。

`FPRMockDirectorProvider`：

- 同一规范化 Snapshot 和同一 Registry 必须产生逐字段一致的 Response。
- 不使用随机数、World Actor 顺序、对象地址、网络、系统区域设置或无界时间输入。

`FPRHttpDirectorProvider`：

- 只通过未来注入的窄 Transport 工作。
- v0.4.0 不提供端点、API Key、认证 Header、远程模型名或正式 Transport。
- `bUseMockDirector=true` 时不得创建 HTTP Request。
- `bUseMockDirector=false` 但没有可用 Transport 时，立即报告 ProviderUnavailable并执行 Mock fallback，不等待超时。
- 自动化只使用进程内 Fake Transport；不得访问互联网。

# Rule DataAsset 与 Registry

`UPRDirectorRuleDataAsset : UPrimaryDataAsset` 固定字段：

- `FGameplayTag RuleId`
- `int32 MaximumLevel = 3`
- `FGameplayTagContainer AllowedReasonTags`
- `TArray<FPRDirectorParameterDefinition> ParameterSchema`
- `FText DisplayName`
- `FText DefaultVisibleReason`
- `FText CounterDescription`

`FPRDirectorParameterDefinition`：

- `FName Name`
- `float Minimum`
- `float Maximum`
- `float DefaultValue`

验证规则：

- RuleId 必须是 Registry 唯一的精确 `Rule.*` Tag。
- MaximumLevel 固定为 3。
- 参数名非 None且唯一；Minimum、Maximum、Default 都必须 finite，满足 `Minimum <= Default <= Maximum`。
- AllowedReasonTags 只能列出现有 GameplayTag。
- DataAsset 不包含执行类、GE、Ability、Room、Reward、Actor 或 Provider 引用。

`UPRDirectorRuleRegistryDataAsset`：

- 只含按字典序排列的四个 `TSoftObjectPtr<UPRDirectorRuleDataAsset>`。
- 只接受：
  - `Rule.CooperationAudit`
  - `Rule.DistanceCorrection`
  - `Rule.RepetitionPenalty`
  - `Rule.SurvivalProtocol`
- 重复、空引用、错误类型、错误 Tag、顺序不一致或 Registry 外 Rule 均导致 Registry 不 Ready。

# Response Validator

`UPRDirectorResponseValidator` 必须依次验证：

1. Request 与 Response Schema 均为 1。
2. Response RequestId 与当前 in-flight Request 完全一致。
3. 未超过 Request 的固定 Deadline。
4. RuleId 存在于已加载 Registry 和当前 CandidateRuleIds。
5. Level Clamp 到 1–3。
6. ReasonTags 最多 8 项，并全部位于对应 Rule DataAsset 的 AllowedReasonTags。
7. Parameters 最多 8 项；参数名唯一、存在于 ParameterSchema、值 finite并按 Schema Clamp。
8. VisibleReason 最多 256 个字符；ExpressionText 最多 512 个字符。
9. 两个文本字段只能展示，不得被解析为命令、对象路径、GameplayTag、JSON、代码、Prompt 或执行参数。

Provider 不可用、超时、格式错误、未知 RuleId、非法 Tag/参数/文本或验证失败均进入一次确定性 Mock fallback。Fallback Response 仍必须经过相同 Validator。若 Mock 也未通过，发布失败事件且不创建 Handle。未知 RuleId 永远不能进入 Applied Rule 层。

# DirectorSubsystem

`UPRDirectorSubsystem : UGameInstanceSubsystem` 是 Provider、Validator、Registry、请求生命周期和 Applied Handle 的唯一所有者。

公共 API：

```text
EPRDirectorRequestStatus RequestEvaluation(FGuid& OutRequestId)
bool GetAppliedRules(TArray<FPRAppliedDirectorRuleHandle>& OutRules) const
EPRDirectorRuleOperationResult RemoveAppliedRule(
    const FPRAppliedDirectorRuleHandle& Handle)
FPRDirectorEvaluationCompletedNative& OnEvaluationCompleted()
FPRDirectorAppliedRuleChangedNative& OnAppliedRuleChanged()
```

规则：

- RequestEvaluation 始终从 `UPRPlayerProfileSubsystem` 获取新的规范化 Snapshot，调用者不能提交任意 Snapshot 或 Response。
- 同一 RuleId 最多存在一个 Active Handle。
- 相同 RuleId、Level 和规范化参数重复应用返回 AlreadyApplied及既有 Handle，不制造重复事件。
- 同 RuleId 的不同 Level/参数以原子替换处理：旧 Handle 失效，新 Handle 使用新 GUID 和递增 ApplySequence。
- Remove 只接受 Subsystem 内部记录的准确 Handle；伪造、篡改或重复移除返回 NotFound，不影响其他 Rule。
- Deinitialize 取消 in-flight Provider Request、清除 Deadline Timer和全部 Handle，不执行 fallback或广播迟到事件。
- v0.4.0 的 Apply/Remove 不修改任何 Gameplay、Room、Reward、UI 或 Save 状态。

# Mock 确定性选择

Mock 只在四项 Registry Rule 中评分：

- RepetitionPenalty：同一 Skill 使用达到固定重复阈值。
- CooperationAudit：QTE 失败/拒绝计数或 Primary Overload 达到固定阈值。
- SurvivalProtocol：Death、低生命或 Divergence 结果达到固定阈值。
- DistanceCorrection：平均 Combat 距离超过固定阈值。

评分只使用规范化 Snapshot；同分按 RuleId 字符串字典序选择。数据不足时固定选择 Level 1 `Rule.SurvivalProtocol`。Rule Level、ReasonTags、参数、VisibleReason 和 ExpressionText 必须完全由 Snapshot 与固定 DataAsset 模板决定。

Mock 只能生成 Registry 中的 Rule。四项规则在 v0.4.0 均无执行效果；十二条正式效果和完整反制业务属于 v0.4.1。

# MCP Operation Manifest

1. 确认唯一 ProjectR Editor、正确项目、PIE=false、初始 Dirty Packages=0。
2. 枚举并审计官方 DataAsset、Object、Asset、Automation 和 PIE Toolset。
3. 确认五个 Create 路径不存在、无碰撞且可编辑。
4. TDD RED 和 BuildEditor 完成后正常重启 Editor，确认所有新反射类型可加载。
5. 串行创建四项 Rule DataAsset，再创建 Registry；不进行并行写入。
6. 逐字段回读 RuleId、MaximumLevel、AllowedReasonTags、ParameterSchema、DisplayName、DefaultVisibleReason、CounterDescription 和 Registry 顺序。
7. 任一字段、类型、顺序、Tag 或引用不符时停止，不保存。
8. 对五项 DataAsset 执行 Data Validation。
9. 只精确保存实际 Dirty 且属于非空 Manifest 的 Package。
10. 查询全局 Dirty Packages，要求意外 Dirty=0。
11. 正常关闭并重启 Editor，重新回读全部五项资产和冻结引用。
12. 打开但不保存固定 Gym，运行 `RunPIEDirectorSmoke()`。
13. StopPIE 后确认 Actor、Subsystem、Provider Request、Timer、Delegate、Handle、测试对象和 Dirty 清理。
14. 生成最终 AutomationReport。

禁止实际互联网访问、Save All、Resave All、Fix Redirectors、普通文件 I/O 修改资产、地图保存或用户 Save 操作。
