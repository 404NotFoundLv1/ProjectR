# ProjectR 原创环境美术纵切片生产工作流设计

> 项目：《首脑协议：共鸣搭档》  
> Unreal 项目：ProjectR  
> 日期：2026-07-31  
> 状态：设计已审阅通过；尚未获得实施授权  
> 目标纵切片：现实世界家园房间 + 第一个网络世界战斗房间  
> 推荐交付档位：Tier A「原创极速档」，12–18 个工作日

## 1. 文档性质与版本边界

本文定义 ProjectR 第一个环境美术纵切片的原创生产工作流、空间构图、资产范围、工具职责、质量门禁与交付挡位。

本文是设计规格，不是当前版本的实施任务合同。仓库当前实施权威仍为 `CURRENT_VERSION.md` 指向的 `v0.7.2`；该版本没有授权创建或修改本规格中的美术资产、地图、DCC 源文件目录或导入配置。

正式制作必须满足以下前置条件：

1. `v0.7.2` 按现有合同完成。
2. 为环境美术纵切片建立新的版本任务合同，明确 Allowed Paths、验收命令和下游消费者。
3. 为 DCC 源文件、导出物和源纹理建立大文件存储 Architecture Decision。
4. 冻结目标硬件和性能阈值。
5. 对所有拟创建 Unreal Package 做冲突与可编辑性检查，并生成 MCP Operation Manifest。

在上述条件满足前：

- 不修改冻结的 `L_RealityHub`、`L_Network_Prototype` 或现有房间注册表。
- 不创建、覆盖、移动、重命名、删除或批量重存任何 `.uasset/.umap`。
- 不改变当前公开 GameplayTags、Blueprint API、序列化字段、资产路径或 SaveGame 合同。

## 2. 已确认的核心决定

| 主题 | 已确认决定 |
|---|---|
| 视角 | 严格按横版 2.5D 构图；角色与战斗处于连续平面主通行带 |
| 现实家园身份 | 废弃游戏店后仓改造的反首脑据点，下接小型地下机房 |
| 现实家园风格 | 半写实、成熟、克制、冷静；暖色只来自卡带、AI、维修和关系痕迹；避免卡通低模 |
| 网络世界身份 | Headmind 人类行为模拟层中的制度化压力测试单元，不是通用霓虹赛博空间 |
| 首个战斗房 | Allocator 主题的 `DA_Room_Allocator_Combat_RationLine`「配给队列」 |
| 资产来源 | 新增环境美术负载不使用第三方最终网格、贴图、材质、贴花、Alpha、HDRI、动画、VFX、音频或 kit |
| AI 边界 | AI 只做原创探索和一次性比例参考；最终几何、拓扑、UV、材质与图形符号由 ProjectR 自有源文件重建 |
| 速度策略 | 先做可升级的 Tier A 原创极速档；不制作一套之后必须丢弃的临时美术 |
| 推荐周期 | 12–18 个工作日完成两个环境房间的 Tier A；人物、敌人、动画、音频另立合同 |

## 3. 目标与非目标

### 3.1 目标

- 建立一条从原创概念探索、DCC 建模与材质，到 Unreal 受控导入的可重复流水线。
- 用两个房间验证 ProjectR 的现实世界与网络世界视觉语言。
- 在横版目标镜头中保证角色、敌人、投射物、命中特效和交互点的优先级。
- 保存可重建的权威源、导出物、来源记录、导入配置与验收证据。
- 让 Codex 承担可自动化的简报、脚本、批处理、导入、检查和记录工作，把人的工作集中在少量审美门禁。
- 让 Tier A 的全部源资产能够直接增量升级到 Tier B/C。

### 3.2 非目标

- 本批不制作新玩家角色、新敌人、骨骼、动画、战斗技能 VFX 或音频。
- 本批不扩建完整现实世界或完整 Allocator 章节。
- 本批不改变战斗、交互、房间选择、存档或 UI 的业务逻辑。
- 本批不以 Nanite、Lumen 或某个具体渲染特性作为未经测量的质量保证。
- 本批不依赖任何单一 AI 服务才能继续生产。
- 本批不承诺 AI 参与内容在全球范围内具有排他版权；只承诺工程来源透明以及不引入第三方最终美术资产。

## 4. 视觉和空间设计

### 4.1 共通横版构图原则

- 角色与玩法对象位于主中景，拥有最高轮廓和局部对比。
- 前景只用稀疏门框、垂线、导轨或暗部遮挡建立纵深，不遮住角色和攻击读数。
- 背景承载世界叙事，但降低对比、细节频率、闪烁和运动幅度。
- 主通行/战斗带连续、地平线明确，首切片不增加平台跳跃或第二层导航规则。
- 摄像机只进行受控的 X 轴横移；装饰纵深不参与角色碰撞。
- 最终取舍以目标游戏镜头中的屏幕占比为准，而不是 DCC 近景观赏效果。

### 4.2 现实世界家园房间

#### 空间身份

废弃游戏店的后仓被改造成反首脑据点。旧商业空间、回收货架、手工修补痕迹与低调的反监控设备共同存在；右侧或后侧露出下沉式小型机房。

#### 横向布局

- 建议可见宽度：22–24 m。
- 建议净高：约 6.5 m。
- 左侧约一半为“关系区”：旧后仓、墓地、记忆墙、卡带和人工维修痕迹。
- 右侧约一半为“系统区”：搭档终端、导演预报器、训练终端和下沉机房背景。
- 地下机房在 Tier A 中可见但不可进入，避免增加第二层导航、楼梯碰撞和额外镜头规则。
- 使用两个可平滑衔接的横向镜头构图，而不是俯视或等距视图。

#### 交互与叙事节点

家园包含五个设备式交互站和一个环境式记忆墙：

1. Echo Cartridge 卡带槽。
2. Graveyard 墓地。
3. Companion Terminal 搭档终端。
4. Training Simulator 训练终端。
5. Director Forecaster 导演预报器。
6. Memory Wall 记忆墙表面组件。

记忆墙作为环境表面资产计数，不和五个独立设备外壳争夺同一级视觉权重。

### 4.3 网络世界首个战斗房

#### 空间身份

首战房使用现有房间定义 `DA_Room_Allocator_Combat_RationLine`。它是 Allocator 的配给队列压力测试单元：玩家被读取身份、排队、计量、施压并裁决额度。

#### 横向布局

- 建议战斗宽度：26–28 m。
- 建议净高：约 7 m。
- 左侧约 20%：身份读取与入口封锁。
- 中部约 60%：配给/战斗压力舱。
- 右侧约 20%：额度裁决与出口闸。
- 核心战斗带连续且无平台跳跃。
- 背景使用观察窗、配额刻度、资源管线和输送结构表达制度压力。
- 闸门关闭后仍需保持敌人、攻击和出口轮廓清楚。

本房间的队列标线、计量表和闸门只提供视觉叙事与空间组织，不在本批中引入新的战斗机制。

## 5. Tier A 原创资产范围

### 5.1 源资产/生成器上限

| 资产组 | 数量上限 | 内容 | 复用边界 |
|---|---:|---|---|
| 共用结构生成器 | 6 | 墙板、门框、地板、梁柱、线缆桥架、设备外壳 | 几何逻辑可共享；现实/网络必须使用不同参数、材质和损耗规则 |
| 现实专属资产 | 10 | 五个设备式交互站、记忆墙、卡带与槽、旧货架/工作台、机房主机等 | 不把现实的温暖旧物语言带入网络 |
| 网络专属资产 | 10 | 身份闸、额度闸、配给台、计量表、观察窗、资源输送和队列设施等 | 服务 Allocator 语义；以后章节只复用底层生成逻辑 |
| 小型陈设基型 | 8 | 箱体、托盘、支架、线束、端子、工具、封条、维护面板 | 从 ProjectR 自有基型生成尺寸和损耗变体 |
| **合计** | **34** | 原创源资产或程序化基型上限 | 不把无意义杂物密度当成质量 |

程序化派生变体不重复计为独立权威源，但必须能够从已版本化的参数和生成器重建。

### 5.2 材质与纹理预算

- 3 张原创 Trim Sheet：现实结构、网络结构、共享道具。
- 2 张原创 Decal Atlas：现实维修/磨损、网络配额/计量图形。
- 5 个项目 Master Material 职责：不透明表面、发光显示、玻璃、贴花、线缆/织物。
- 只允许最多 4 个英雄资产使用独立 2K PBR 纹理集。
- 其余资产优先使用 Trim、Atlas、顶点色和 Material Instance 参数。
- Unreal 纹理输出使用明确的通道打包配置；ORM 通道顺序由正式导入合同和自动检查冻结。
- 不使用下载的扫描材质、现成 Smart Material 外观、第三方污渍/刮痕 Alpha 或外部 HDRI 作为最终负载。

### 5.3 暂定几何护栏

这些数值只用于防止明显失控，必须在目标镜头和目标硬件上测量后才能转为验收阈值：

- 结构模块：约 2k–15k 三角面。
- 英雄交互站：约 15k–40k 三角面。
- 小型道具：约 0.5k–8k 三角面。

不以“模型面数更高”替代轮廓、材质值域或战斗可读性。是否使用 Nanite/LOD 按资产类别和实测结果逐项决定。

## 6. 生产架构

### 6.1 六阶段主流程

1. **合同与存储门禁**：版本任务、Allowed Paths、资产命名扩展、大文件 ADR、LFS 容量和恢复测试。
2. **资产简报**：空间职责、目标镜头、真实尺度、轮廓、材质、复用、碰撞和验收标准。
3. **原创概念与设计板**：AI 加速探索，ProjectR 统一设计，多视图和尺寸冻结。
4. **DCC 权威源**：Blender 负责最终几何，Substance 负责最终材质源，生成器和导出脚本版本化。
5. **隔离 Unreal 导入**：先进入新建的美术验证地图，不改现有冻结地图或注册表。
6. **镜头与技术验收**：目标镜头、玩法可读性、引用、性能、来源和干净环境重建共同通过。

### 6.2 单资产标准生产通道

#### 01. 资产简报

每个资产必须先有机器可读和人可读的简报，至少包含：

- 稳定语义 ID 和中文职责说明。
- 所属房间、优先级 P0/P1/P2。
- 目标镜头占比、实际尺寸和参照人物。
- 主/次轮廓关键词及禁止造型。
- 模块网格、枢轴、碰撞和可复用边界。
- 材质职责、纹理预算和发光/透明限制。
- 依赖、下游使用点和验收截图位置。
- 来源要求和允许的 AI 中间输入。

Codex 可以批量生成简报初稿；艺术方向仍在 G1 由用户签收。

#### 02. 原创探索图

- 图像生成器只输出剪影、构成和材质方向候选。
- 不使用第三方图片拼贴成最终设计。
- 保存提供方、模型/版本（若可获得）、提示词、负面约束、种子或任务 ID、生成日期、选中/淘汰理由。
- AI 服务失败或不可用时，直接由 Blender 灰模、Grease Pencil 或 Krita 设计板继续；AI 不是关键路径依赖。
- 任何 AI 生成贴图不得直接进入游戏。
- 任何 AI 生成网格如用于观察，只能作为一次性比例参考，不能导入最终包，也不能成为 Blender 权威源的隐藏依赖。

#### 03. 统一设计板（G1）

ProjectR 重新组织并校正探索结果，产出同一设计的：

- 目标横版侧视图。
- 正视、背视和必要剖面。
- 关键尺寸、模块边界、活动部件、材质分区。
- 与 180 cm 人体及房间地平线的比例图。
- 现实/网络视觉语言检查。

多视图结构矛盾时，回退并重画统一设计板；不得直接从相互矛盾的 AI 单图进入高模。

#### 04. Blender 灰模（G2）

- Blender 是几何权威源。
- 使用真实尺度、稳定枢轴、模块网格和可重复的命名映射。
- 先完成轮廓、开合关系、接缝和碰撞代理，再进入表面细化。
- Geometry Nodes、Python 和非破坏修改器用于生成 ProjectR 自有变体。
- 灰模必须先导入隔离地图，在目标横版镜头验证角色遮挡、战斗净空和模块接缝。
- 尺度、枢轴、法线或接缝问题必须回到 Blender 源和导出脚本修复，不在 Unreal 中逐个手工掩盖。

#### 05. 终模、UV 与材质

- 最终网格由 ProjectR 在 Blender 中重建，包含可解释的拓扑、UV、法线、枢轴和碰撞代理。
- 英雄资产可以高低模烘焙；结构和常规道具优先使用 Trim/Atlas。
- Substance Designer/Painter 用于原创程序材质、烘焙、Trim、Atlas 和少量英雄纹理。
- 可以使用软件算法和基础滤镜，但不使用第三方资产包、扫描内容或现成外观作为最终表面。
- 所有导出都由版本化预设/脚本生成，并记录源文件哈希、导出配置和时间。

#### 06. 受控导入 Unreal（G3）

- 正式静态网格导入基线使用 UE 5.8 支持的 FBX 管线；精确 FBX 版本和导入设置写入任务合同与自动化预设。
- 写入前列出精确 Package 路径，检查存在、可编辑和碰撞状态。
- 所有 MCP 写入串行发送到同一个 ProjectR Editor 实例。
- 每批分别验证网格、贴图、材质实例、碰撞和地图摆放。
- 只保存 Manifest 中的精确 Packages，随后复查 Dirty Packages、引用和导入日志。
- 静态资产没有 Blueprint 编译步骤时不得把“资产创建”误报成“Blueprint 编译通过”。
- 若某资产涉及 Blueprint，分别报告创建、编译、保存、重启加载和 PIE 状态。

#### 07. 最终镜头验收（G4）

使用固定角色位置、摄像机位置、灯光状态和渲染设置生成前后对比截图，检查：

- 角色、敌人、投射物、命中特效优先级。
- 交互点在预期距离内可识别。
- 背景对比、细节频率、闪烁和运动不过量。
- 两个世界视觉语言区别清楚，但仍属于同一游戏。
- 目标硬件性能达到正式合同阈值。
- Package、引用、来源台账和可重建证据齐全。

## 7. 工具与人的职责

| 参与者/工具 | 负责 | 不负责 |
|---|---|---|
| Codex | 资产简报、概念提示、Blender Python/Geometry Nodes 辅助、导出脚本、MCP Manifest、批量检查、截图对比、来源台账、日志和失败定位 | 不自行宣布主观美术质量通过；不通过普通 IO 写 `.uasset/.umap` |
| 图像生成器 | 快速产生原创剪影、构成和表面方向候选 | 不提供最终游戏贴图或最终网格；不成为生产的单点依赖 |
| Blender | 几何权威源、真实尺度、拓扑、UV、法线、枢轴、模块变体、碰撞代理和导出 | 不依赖不可追溯的下载模型、材质或 kit |
| Substance | 材质权威源、原创程序材质、Trim、Atlas、烘焙和英雄纹理 | 不直接采用第三方扫描材质或预制外观作为最终表面 |
| Unreal MCP | Package 检查、导入、材质实例、放置、精确保存、日志、截图和验证 | 不越过版本合同；不覆盖、移动、删除或全量重存现有资产 |
| 用户 | G1 设计冻结、G2 场景灰模和 G4 最终镜头的批次审美选择 | 不需要手工建模、画贴图或逐项点击导入设置 |

## 8. 权威源、派生物与来源记录

以下目录是设计目标，正式路径仍需在新任务合同和大文件 ADR 中批准：

```text
Docs/Art/
  Briefs/                    # 资产简报与设计板引用
  Reviews/                   # G1/G2/G4 批次签收记录

SourceArt/ProjectR/
  Concepts/                  # 生成任务记录和 ProjectR 修订设计板
  Blender/                   # 几何权威源 .blend
  Substance/                 # 材质权威源 .spp/.sbs
  Generators/                # ProjectR 自有脚本和节点组
  Provenance/AssetLedger.*   # 来源、人工步骤、哈希和许可说明
  Exports/                   # 可重建的 FBX 和纹理导出物

/Game/ProjectR/Art/...       # Unreal 运行时派生资产
```

### 8.1 Asset Ledger 最低字段

- Asset ID 和 UE Package 路径。
- 所属房间和批次。
- 权威 `.blend` / `.spp` / `.sbs` 路径及哈希。
- 导出物路径及哈希。
- 概念来源记录和人工重建设计说明。
- 第三方最终资产检查结果。
- 生成器/导出脚本版本。
- G1/G2/G3/G4 状态、审阅日期和证据位置。

### 8.2 原创性边界

“全原创”在本规格中的可验收含义是：

- 新增纵切片环境负载不包含外部作者制作的最终网格、贴图、材质、贴花、Alpha、HDRI、动画、VFX、音频或 kit。
- 可以观察外部作品作为研究参考，但不得复制独特设计、描摹、拼贴或把参考文件打包进最终资产。
- 可以使用 Blender、Substance、Unreal 和图像生成服务的软件能力；软件工具本身不等于第三方最终美术资产。
- AI 输出必须经过 ProjectR 统一设计、几何重建和原创材质生产，且保留来源链。
- 本规则不替代知识产权法律意见，也不承诺 AI 参与内容的排他版权。

## 9. 隔离地图与集成边界

后续任务可考虑创建以下隔离验证地图；名称尚未构成公开 Package 合同：

```text
/Game/ProjectR/Art/VerticalSlice/Maps/L_ArtSlice_RealityHub
/Game/ProjectR/Art/VerticalSlice/Maps/L_ArtSlice_AllocatorRationLine
```

创建前必须：

- 按 `AssetNaming.md` 和新增美术类型前缀决议冻结精确名称。
- 检查 Package 是否已存在、是否可编辑、是否有大小写或语义冲突。
- 在 Operation Manifest 中列出精确创建和修改范围。
- 优先复用现有玩法 Actor/API 作为只读依赖，不修改其公开合同。

只有隔离地图完成 G1–G4、性能和未来兼容性检查后，才能另立集成任务评估如何进入 `L_RealityHub`、`L_Network_Prototype` 或正式章节地图。

## 10. 质量门禁与失败回退

### G1：设计一致

- 多视图结构不矛盾。
- 侧视剪影在目标镜头可读。
- 尺度和模块关系明确。
- 现实/网络语言没有串味。

失败时回退到统一设计板，不进入高模或纹理。

### G2：场景灰模成立

- 厘米尺度、地平线、枢轴、角色遮挡、模块接缝和战斗净空在隔离地图成立。
- 交互站和战斗出口能被识别。

失败时修 Blender 权威源、空间布局或摄像机规则，不用细节和灯光掩盖问题。

### G3：资产技术健康

- 命名和路径无冲突。
- 法线、UV、纹理通道、碰撞和导入设置正确。
- 精确 Packages 已保存，无意外 Dirty Packages 或缺失引用。
- Asset Ledger 和重建信息完整。

失败时回到对应源文件或导出/导入预设修复；不得只修 UE 派生结果。

### G4：目标镜头有效

- 角色、敌人和战斗反馈优先级正确。
- 背景不过度高频、过亮或频闪。
- 交互点和出口清楚。
- 目标硬件性能达到冻结阈值。

“画面漂亮但战斗读不清”时先降低背景对比、密度和运动，再调整灯光/材质值域，最后才删减结构资产。

## 11. 交付挡位

### Tier A：原创极速档（推荐）

- 周期：12–18 个工作日。
- 两张隔离美术验证地图。
- 34 个原创源资产/生成器基型上限。
- 3 Trim、2 Decal Atlas、5 Master Material 职责。
- 现实家园的五个设备式交互站和记忆墙视觉外壳。
- Allocator 配给队列完整战斗构图。
- 来源台账、可重建导出、受控导入和目标镜头 QA。

### Tier B：展示级纵切片

- 周期：累计 20–30 个工作日。
- 在 Tier A 基础上增加约 12–18 个原创专属资产。
- 关键站点二次设计和独立高精度纹理。
- 两房间专属环境 VFX、受控动态材质和更多叙事层。
- 最终展示镜头的灯光/后处理精调及额外性能收敛。

### Tier C：发行基准档

- 周期：累计 35–50 个工作日。
- 完整独特资产和近景检视质量。
- 可扩展的现实/网络程序材质库。
- 正常、警戒、战后/故障等状态变体。
- 环境动画、屏幕内容、章节级 VFX 语言、多档画质和目标硬件专项优化。
- 形成后续房间可复用的生产模板和自动化测试。

所有挡位共享同一批权威源。预算增加用于更多原创设计迭代、细化、状态和验证，不用于购买第三方资产。

## 13. 赶工优先级

### P0：不可删除

- 地面、墙体、门闸和主轮廓。
- 交互站与出口轮廓。
- 战斗净空、碰撞和基础材质值域。
- 来源记录、权威源和重建能力。

### P1：主体质量

- 卡带槽、搭档终端、配给台和额度表等英雄节点。
- 核心 Trim/Decal。
- 背景机房、观察窗和关键灯光。

### P2：可以延后

- 更多杂物和尺寸变体。
- 远景细件、局部环境动画和额外状态。
- 不影响叙事、交互和玩法可读性的微表面细节。

工期风险只通过缩减 P2 处理。来源台账、可重建源、UE 灰模和战斗可读性不是 polish，不得删除。

## 14. 大文件、仓库和恢复策略

当前仓库的大文件规则主要覆盖 `.uasset/.umap`，不应直接开始加入 DCC 文件。正式制作前必须通过 Architecture Decision 明确：

- 哪些 DCC 源和稳定导出物进入 Git LFS，例如 `.blend`、`.spp`、`.sbs`、`.fbx`、源 `.png/.tga/.exr`。
- 哪些可重建缓存、自动备份和临时烘焙进入 ignore。
- 概念生成记录、设计板和 Asset Ledger 的普通 Git/LFS 边界。
- 远端 LFS 容量预算、配额告警和增长估算。
- Blender/Substance/FBX/纹理格式的版本兼容策略。
- 备份、归档和恢复责任。

可靠性验收必须至少包含一次干净克隆测试：拉取 LFS 内容，在文档化依赖下从一个代表性 `.blend` 和材质源重新生成导出物，并验证其哈希或允许差异，再由 Unreal 重新导入到测试根或隔离 Package。

## 15. 每批资产 Definition of Done

一个资产批次只有同时满足以下条件才算完成：

- [ ] Asset Brief、统一设计板和批次审批记录齐全。
- [ ] `.blend` / `.spp` / `.sbs` 或程序源可以重建导出物。
- [ ] Asset Ledger 确认没有第三方最终美术负载。
- [ ] 尺度、枢轴、法线、UV、纹理打包和碰撞检查通过。
- [ ] 写入前 Package Manifest、冲突检查和 Allowed Paths 检查通过。
- [ ] 精确 UE Packages 已保存，无意外 Dirty Packages、引用缺失或导入错误。
- [ ] 隔离地图固定镜头截图通过。
- [ ] 相关 PIE/自动化测试未发现现有玩法退化。
- [ ] 目标硬件性能已测量并达到正式合同阈值。
- [ ] Future Compatibility Review 已覆盖直接下游消费者。

如果目标硬件或性能阈值尚未冻结，对应项必须报告 `NOT RUN`，不得宣称通过。

## 16. 未来兼容性审查

正式任务需要检查至少以下消费者：

- `L_RealityHub` 及其交互站引用。
- `L_Network_Prototype`、房间注册表及 `DA_Room_Allocator_Combat_RationLine`。
- 现有角色横版移动、碰撞、相机和战斗 Actor。
- 交互 UI、Director Forecaster、Training Simulator、Companion Terminal、Graveyard 和 Echo Cartridge Slot 的现有公开接口。
- 房间加载、保存、重启恢复和版本迁移路径。
- 后续章节对共享结构生成器、材质职责和命名合同的依赖。

环境美术只能消费现有公开接口；不得让 Combat 反向依赖具体房间、章节、QTE、Director Rule、对话或 UI 类。

## 17. 风险与缓解

| 风险 | 缓解 |
|---|---|
| AI 图像服务不可用或输出不一致 | AI 不是关键路径；用 Blender 灰模/Krita 继续；G1 统一多视图后才进入建模 |
| “全原创”被误解为排他版权保证 | Asset Ledger 记录工程来源和人工重建；明确法律边界；必要时寻求专业法律意见 |
| 为追求速度跳过灰模导致高成本返工 | G1/G2 是强制门禁；终模和纹理不得早于空间验证 |
| DCC 文件挤爆仓库或只在本机可用 | 大文件 ADR、LFS 预算、缓存忽略、干净克隆重建测试 |
| UE 导入产生路径冲突或意外脏包 | 精确 Manifest、存在性检查、单 Editor 串行写入、精确保存和 Dirty Package 复查 |
| 背景细节破坏横版战斗可读性 | 固定镜头截图、角色/敌人/投射物优先级、先降背景对比和运动 |
| 资产范围扩张 | 34 源资产上限，P0/P1/P2 管理，人物/敌人/动画/音频另立合同 |
| 提前修改冻结地图和公共引用 | 先用隔离地图；正式集成另立版本任务和兼容性审查 |

## 18. 实施前仍需冻结的输入

这些输入不阻止本设计规格成立，但会阻止正式制作开始：

1. 新环境美术任务的版本号、Allowed Paths 和验收命令。
2. 目标硬件、分辨率、帧率和画质档位。
3. DCC/导出/运行时资产的最终前缀和 Package 路径。
4. Git LFS 精确扩展名、容量预算和备份策略。
5. Blender、Substance 和 FBX 导出预设的冻结版本。
6. 隔离地图最终名称和与现有 gameplay actor 的只读连接方式。

## 19. 建议执行顺序

1. 当前 `v0.7.2` 完成后，为本设计建立独立美术版本任务。
2. 先完成大文件 ADR、目录和一个代表性资产的端到端烟雾测试。
3. 按 Tier A 生产两个房间并完成 G1–G4。
4. 在实机战斗和来源/恢复测试通过后，选择停在 Tier A 或增量进入 Tier B/C。
5. 人物、敌人、动画、战斗 VFX 和音频使用同样原创性原则，但另写生产规格和任务合同。
